# Phase 3 Empirical Comparison Results

Generated by `node scripts/research/compare.mjs` → `compare-results.json`.

**IMPORTANT — data limitation:** this dev environment has NO Tickerbot API
key (the key exists only in the app's secure store on the user's device), so
all numbers below come from **deterministic seeded synthetic fixtures**
(1,254 weekday bars per ticker, regime-switching drift/vol, see
`gen-bars.mjs`). They validate methodology behavior — selectivity, gating,
leakage-safety, determinism — **not live-market edge**. To re-run on real
bars later: cache them as JSON arrays of `{t,o,h,l,c,v}` and run
`node scripts/research/compare.mjs --bars-file <file> TICKER`.

## Headline finding (honest)

**No configuration reliably beats simple baselines across tickers.** Most
variants show negative edge vs the best of {dominant-direction, always-up,
momentum} baselines. Apparent high accuracies at ~2–5% coverage
(e.g., composite+edgeGate 60% on AAPL) rest on 3–7 signals — exactly the
misleading tiny samples the MIN_SIGNAL_SAMPLE / Wilson-CI gating exists to
expose. Ablations are inconsistent across tickers (each feature group helps
on one ticker and hurts on another) ⇒ all features retained.

## Walk-forward parameter selection (train 60% → validation 20% → test 20%)

Chosen configs varied per ticker (threshold-1.5 ×3, topk-0.05 ×2); test edges
remained within ±5 pp of baseline everywhere. Parameter provenance is recorded
per ticker in compare-results.json (`paramSearch.validationScores`).

## Decision

Ship the principled defaults (matchMode 'topk', adaptive K, percentile gate,
MIN_SIGNAL_SAMPLE=30, Wilson CI disclosure) because they are selective,
leakage-safe and honest — NOT because they demonstrate an edge. The engine
correctly answers "no statistically meaningful directional edge found" on
this data.
